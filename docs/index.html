1. Создание веб-сайта

Обзор

Веб-сайты Кварто - это удобный способ публикации групп документов. Документы, публикуемые как часть веб-сайта, имеют общие элементы навигации, параметры отображения и визуальный стиль.

Навигация по веб-сайту может осуществляться с помощью глобальной панели навигации, боковой панели со ссылками или комбинации того и другого для сайтов с несколькими уровнями контента. Вы также можете включить полнотекстовый поиск по веб-сайтам.

Веб-сайты Quarto могут публиковаться в самых разных местах назначения, включая страницы GitHub, Netlify, Posit Connect или любую другую службу статического хостинга или веб-сервер интрасети. Смотрите документацию по публикации веб-сайтов для получения дополнительной информации.

Создание ссылок

При создании ссылок между страницами вашего сайта вы можете указать исходный файл в качестве целевой ссылки (а не .html файл). Вы также можете добавить хэш-идентификаторы (#) в исходный файл, если хотите создать ссылку на определенный раздел документа. Например:

[about](about.qmd) [about](about.qmd#section)

Одним из преимуществ использования этого стиля ссылок в отличие от прямого таргетинга на .html файлы является то, что если вы в какой-то момент преобразуете свой сайт в формат книги, ссылки на файлы автоматически преобразуются в ссылки на разделы для форматов, которые создают отдельный файл (например, PDF или MS Word).

Узнать больше

После того, как у вас будет запущен базовый веб-сайт, ознакомьтесь с этими статьями о различных способах улучшения вашего сайта:

  • Навигация по веб-сайту описывает различные способы добавления навигации на веб-сайт, включая панели навигации верхнего уровня, боковые панели или гибридные конструкции, использующие и то, и другое. В этой статье также рассматривается добавление полнотекстового поиска, а также нижнего колонтитула по всему сайту.

  • Инструменты для веб-сайта включают добавление метаданных социальных сетей (например, для карточек Twitter) и Google Analytics на ваш сайт, а также предоставление пользователям возможности переключаться между темной и светлой цветовыми схемами.

  • Параметры веб-сайта предоставляют исчерпывающую ссылку на все доступные параметры веб-сайта.

  • Выполнение кода содержит советы по оптимизации рендеринга сайтов с большим количеством документов или дорогостоящих вычислений.

  • Публикация веб-сайтов перечисляет различные варианты публикации веб-сайтов, включая GitHub Pages, Netlify и Posit Connect.

2. Навигация по web-сайту

Обзор

Для обеспечения навигации по веб-сайту доступно множество опций, в том числе:

  • Использование верхней навигации (навигационной панели) с дополнительными подменю.

  • Использование боковой навигации с иерархией страниц.

  • Сочетание верхней и боковой навигации (где верхняя навигация ссылается на разные разделы сайта с их собственной боковой навигацией).

Кроме того, вы можете добавить полнотекстовый поиск в верхний или боковой интерфейс навигации.

Лучшая навигация

Чтобы добавить верхнюю навигацию на веб-сайт, добавьте navbar запись в website конфигурацию в _quarto.yml. Например, следующий YAML:

website:
  navbar:
    background: primary
    foreground: success
    pinned: true
    search: true
    menu:
      - text: "Quarto Web Learning"
    icon: "upload"
    text: "Conspect"
    left:
      - text: "Home"
        file: index.qmd
      - talks.qmd
      - about.qmd

Выше мы использовали left опцию, чтобы указать элементы для левой части панели навигации. Вы также можете использовать right опцию, чтобы указать элементы для правой части.

Текст для элементов панели навигации будет взят из заголовка базового целевого документа. Обратите внимание, что в приведенном выше примере мы предоставляем пользовательское text: "Home" значение для index.qmd.

Вы также можете создать меню панели навигации, включив в него a menu (который представляет собой список элементов, очень похожих на left и right). Например:

left:
  - text: "More"
    menu:
      - talks.qmd
      - about.qmd

Инструменты навигационной панели

Уведомление

Функция Quarto 1.3 - 1.4

Эта функция является новой в Quarto 1.3, которую вы можете скачать по адресу: https://quarto.org/docs/download /

Основные моменты

Quarto 1.4 включает в себя следующие новые функции:

  • Рукописи Quarto - новый тип проектов для научных статей, где записные книжки являются как источником статьи, так и частью опубликованной записи.

  • Панели мониторинга Quarto - Новый формат для создания интерактивных панелей мониторинга.

  • Typst Format— Поддержка typst выходного формата. Typst - это новая система набора текста с открытым исходным кодом на основе разметки, которая должна быть такой же мощной, как LaTeX, но при этом намного проще в освоении и использовании.

  • Shiny для Python — Поддержка использования Shiny для Python в документах Quarto.

  • Встроенное выполнение для Jupyter — поддержка выполнения встроенных выражений при использовании ядер Jupyter.

  • Рендеринг скриптов для Jupyter — поддержка рендеринга файлов скриптов (например, .py, .jl или .r), которые специально отформатированы как записные книжки.

  • Простая настройка Binder для проектов Quarto - Поддержка генерации файлов, необходимых для развертывания проекта Quarto с использованием Binder.

  • Обработка изображений и рисунков лайтбоксом — поддержка масштабирования изображений и рисунков с помощью lightbox. Включает поддержку группировки нескольких изображений в галерею.

  • Изменения в Lua—Quarto v1.4 добавляет новые возможности для разработчиков фильтров Lua.

  • Изменения в перекрестных ссылках—версия Quarto v1.4 делает элементы с перекрестными ссылками более мощными и общими.

  • Изменения в обработке таблиц—Quarto v1.4 улучшает обработку таблиц HTML, добавленную в версии v1.3.

В дополнение к традиционной навигации, панель навигации также может отображать набор инструментов (например, действия в социальных сетях, действия по просмотру или редактированию GitHub и т.д.) Определение инструмента состоит из названия значка и href, по которым нужно переходить при нажатии.  Для обозначения значка используйте название любого из более чем 1300 значков начальной загрузки.

Например:

website:
  navbar:
    tools:
      - icon: twitter
        href: https://twitter.com
      - icon: github
        menu:
          - text: Source Code
            url:  https://code.com
          - text: Report a Bug
            url:  https://bugs.com

Инструменты, указанные для панели навигации, появятся в правой части панели навигации. Если вы укажете темную тему или режим чтения для вашего веб-сайта, элементы управления для этих параметров появятся с любыми указанными инструментами.

Когда панель навигации сворачивается в меню на экранах меньшего размера, инструменты будут размещены в нижней части меню.

Боковая навигация

Если ваш сайт состоит из более чем нескольких документов, вы можете предпочесть использовать боковую навигацию, которая позволяет отображать произвольно глубокую иерархию статей.

Если вы читаете эту страницу на настольном устройстве, то слева вы увидите боковой навигационный дисплей по умолчанию (в противном случае вверху вы увидите строку заголовка, на которую вы можете нажать, чтобы открыть навигацию).

Чтобы добавить боковую навигацию на веб-сайт, добавьте sidebar запись в website раздел _quarto.yml. Например:

website:
  sidebar:
    style: "docked"
    search: true
    contents:
      - section: "Basics"
        contents:
          - index.qmd
          - basics-knitr.qmd
          - basics-jupyter.qmd
      - section: "Layout"
        contents:
          - layout.qmd
          - layout-knitr.qmd
          - layout-jupyter.qmd

Доступно два стиля боковой навигации: “docked”, при котором навигация отображается на боковой панели с особым цветом фона, и “floating”, при котором навигация располагается ближе к основному тексту. Вот как выглядят “закрепленный” и “плавающий” стили (соответственно):

Автоматическое создание

Выше мы описали, как явно заполнить contents вашу боковую панель элементами навигации. Вы также можете автоматически создавать боковую навигацию из файловой системы. Самый простой способ сделать это - указать contents опцию следующим образом

sidebar:
  contents: auto

Использование contents: auto на корневом уровне приведет к включению в навигацию всех документов вашего веб-сайта (за исключением домашней страницы, на которую можно перейти по ссылке заголовок). Навигация построена с использованием следующих правил:

  1. Названия элементов навигации будут считываться из title поля документов.

  2. Подкаталоги создадут разделы, названия которых будут автоматически определяться на основе названия каталога (включая добавление заглавных букв и замену пробелов тире и подчеркивания). Используйте index.qmd в каталоге, чтобы указать явный title параметр, если вам не нравится автоматический.

  3. Порядок в алфавитном порядке (по имени файла), если в метаданных документа не указано числовое order поле.

Автоматическая навигация автоматически включает элементы в подкаталоги. Если вы предпочитаете этого не делать, используйте явный /* для указания только документов в корневом каталоге:

sidebar:
  contents: /*

Вместо указания того, что должны быть включены все документы, вы также можете указать имя каталога или шаблон глобуса.  Например, все следующие значения для contents являются допустимыми (обратите внимание, что вторая форма для reports нерекурсивна):

sidebar:
  contents: reports
  
sidebar:
  contents: reports/*
  
sidebar:
  contents: "*.ipynb"

Обратите внимание, что в YAML нам нужно заключать в кавычки любые строки, начинающиеся с * (как мы делаем выше для *.ipynb).

Вы можете автоматически создавать боковую панель contents в любом месте иерархии боковых панелей. Например, здесь мы добавляем раздел, который автоматически создается из каталога:

sidebar:
  contents:
    - about.qmd
    - contributing.qmd
    - section: Reports
      contents: reports

Вы также можете включить автоматически созданные элементы в середину списка обычных элементов, включив элемент с auto свойством.  Здесь мы добавляем auto запись в середину списка элементов:

sidebar:
  contents:
    - about.qmd
    - contributing.qmd
    - auto: "*-report.qmd"

Еще раз обратите внимание, что мы цитируем auto запись с * в ней, чтобы она была правильно проанализирована.

Инструменты боковой панели

В дополнение к традиционной навигации, боковая панель также может отображать набор инструментов (например, действия в социальных сетях, действия по просмотру или редактированию GitHub и т.д.) Определение инструмента состоит из названия значка и href, по которым нужно переходить при нажатии. Для icon используйте название любого из более чем 1300 значков начальной загрузки.

Например:

website:
  sidebar:
    tools:
      - icon: twitter
        href: https://twitter.com
      - icon: github
        menu:
          - text: Source Code
            url:  https://code.com
          - text: Report a Bug
            url:  https://bugs.com

Гибридная навигация

Если у вас веб-сайт с десятками или даже сотнями страниц, вы, вероятно, захотите использовать верхнюю и боковую навигацию вместе, где верхняя навигация ссылается на различные разделы, каждый со своей собственной боковой навигацией.

Для этого укажите группу sidebar записей и свяжите каждую группу sidebar записей с navbar записью, сопоставив их title имена и указав страницу, на которую дана ссылка, navbar в качестве первого контента в sidebar группе. Например, если вы используете Diátaxis Framework для документации, у вас могут быть отдельные разделы для руководств, практических руководств, пояснений и справочных документов, ваша страница может выглядеть следующим образом.

При гибридной навигации, если затем вы нажмете, скажем, на учебные пособия, вы можете попасть на страницу, подобную следующей.

Для достижения такого макета конфигурация вашего сайта должна выглядеть примерно так:

website:
  title: ProjectX
  navbar:
    background: primary
    search: true
    left:
      - text: "Home"
        file: index.qmd
      - text: "Tutorials"
        file: tutorials.qmd
      - text: "How-To"
        file: howto.qmd
      - text: "Fundamentals"
        file: fundamentals.qmd
      - text: "Reference"
        file: reference.qmd

  sidebar:
    - title: "Tutorials"
      style: "docked"
      background: light
      contents:
        - tutorials.qmd
        - tutorial-1.qmd
        - tutorial-2.qmd

    - title: "How-To"
      contents:
        - howto.qmd
        # navigation items

    - title: "Fundamentals"
      contents:
        - fundamentals.qmd
        # navigation items

    - title: "Reference"
      contents:
        - reference.qmd
        # navigation items

Навигация по страницам

Если у вас есть веб-сайт с несколькими страницами в разделе или подразделе, часто бывает удобно предложить пользователю возможность перейти к следующей странице (или предыдущей странице) внизу страницы, которую он только что закончил читать. Вы можете включить это с помощью:

website:
  page-navigation: true

При включении навигация по страницам будет отображаться внизу страницы всякий раз, когда есть следующая или предыдущая страница (в том числе в следующем или предыдущем разделе). Эта опция включена по умолчанию для книг, но не для веб-сайтов.

Разделители

Если вы добавите разделитель страниц на боковой панели (либо между разделами, либо между элементами), элементы управления навигацией по страницам не будут отображаться для продолжения разбивки по страницам через разделитель. Например, на следующей боковой панели:

website:
  sidebar:
    contents:
      - section: "First Section"
        contents:
          - href: document1.qmd
          - href: document2.qmd
          - href: document3.qmd
      - text: "---"
      - section: "Second Section"
        contents:
          - href: document4.qmd
          - href: document5.qmd
          - href: document6.qmd

Когда пользователь дойдет до конца document3.qmd, он увидит предыдущую навигацию, чтобы вернуться к document2.qmd, но он не увидит следующую навигацию для перехода к документу 4. Такое поведение полезно, когда у вас есть разделы содержимого, которые естественным образом не располагаются друг за другом в последовательном порядке. Используйте разделитель, чтобы обозначить это на боковой панели горизонтальной линией и разбить разбивку на страницы.

Кнопка наверх

Вы можете включить ссылку “Назад к началу” в нижней части документов на веб-сайте, используя back-to-top-navigation опцию. Например:

website:
  back-to-top-navigation: true

Обратите внимание, что вы можете отключить постраничную навигацию назад к началу, указав back-to-top-navigation: false.

Нижний колонтитул страницы

Используйте page-footer опцию для создания общего нижнего колонтитула для всех страниц веб-сайта. Самый простой нижний колонтитул содержит текст, который будет располагаться по центру и отображаться более легким шрифтом:

website:
  page-footer: "Copyright 2023, Eduard Soldatkin"

В качестве альтернативы вы можете настроить таргетинг на left, right и center области нижнего колонтитула по отдельности:

website:
  page-footer: 
    left: "Copyright 2021, Norah Jones" 
    right: 
      - icon: github
        href: https://github.com/
      - icon: twitter 
        href: https://twitter.com/

Примечание для right области нижнего колонтитула мы включили элементы навигации для GitHub и Twitter, а не текст. Вы можете включить элементы навигации в любую область нижнего колонтитула.

Вы можете использовать опции background, foreground и border для дальнейшего управления внешним видом нижнего колонтитула. По умолчанию нижний колонтитул не имеет цвета фона и верхней границы. Чтобы устранить границу, вы должны сделать это:

website:
  page-footer:
    border: false

Чтобы использовать светлый фон (например, в тон панели навигации), вам следует сделать следующее:

website:
  page-footer:
    background: light

Если не указано иное, цвет (foreground), используемый для элементов, отображаемых в нижнем колонтитуле, будет определяться автоматически с использованием цвета, контрастирующего с фоном нижнего колонтитула.

Скрытие навигации

Для некоторых страниц (особенно с полностью настраиваемым макетом) вы можете полностью скрыть навигацию (navbar, sidebar или и то, и другое). В этом случае добавьте следующее в начало страницы:

# Hides the sidebar on this page
sidebar: false

# Hides the navbar on this page
navbar: false

Режим чтения

Если вы хотите, чтобы пользователи могли скрывать боковую навигацию и оглавление и более сосредоточенно читать, вы можете включить эту функцию reader-mode. При включении reader-mode переключатель появится на панели навигации, если таковая имеется, или на боковой панели. При нажатии переключатель ‘свернет’ боковую панель и оглавление.

Чтобы включить reader-mode, используйте следующее в своем проекте:

website:
  reader-mode: true

Поиск по сайту

Вы можете добавить поиск по сайту, включив его search: true в свою site-navbar или site-sidebar конфигурацию. Например:

website:
  sidebar:
    style: "docked"
    search: true
    items:
      - text: "Basics"
        contents:
          - index.qmd
          - basics-jupyter.md
        # etc

Ссылки на GitHub

Вы можете добавлять различные ссылки (например, на редактирование страниц, сообщать о проблемах и т.д.) В репозиторий GitHub, где размещен исходный код вашего сайта. Для этого добавьте repo-url вместе с одним или несколькими действиями в repo-actions. Например:

website:
  repo-url: https://github.com/quarto-dev/quarto-demo
  repo-actions: [edit, issue]

Существует несколько дополнительных опций, которые позволяют настроить поведение ссылок на репозитории:

Опция Описание
repo-subdir Подкаталог репозитория, содержащий исходные файлы (по умолчанию используется корневой каталог).
repo-branch Ветка репозитория, содержащая исходные файлы (по умолчанию - main)
issue-url Укажите явный URL-адрес для действия ‘Сообщить о проблеме’.

Перенаправления

Если вы переименовываете или перемещаете страницу на своем сайте, вам может потребоваться создать перенаправления со старых URL-адресов, чтобы существующие ссылки не прерывались. Вы можете сделать это, добавив aliases со старых страниц на переименованные страницы.

Допустим, вы переименовали page.qmd в renamed-page.qmd. Для создания перенаправления вам следует добавить следующую aliases запись в renamed-page.qmd:

---
title: "Renamed Page"
aliases:
  - page.html
---

Это также может быть полезно в ситуациях, когда вы реорганизуете контент на своем сайте в другую иерархию каталогов или разбиваете одну большую статью на более мелкие. В этом случае вы можете захотеть добавить хэш URL-адреса раздела, который вы взломали, на новую страницу. Например:

---
title: "Learning More"
aliases:
  - overview.html#learning-more
---

Совет

В зависимости от того, где вы развертываете свой сайт, могут быть доступны более мощные инструменты для определения перенаправлений на основе шаблонов. Например, Netlify _redirects files или .htaccess файлы. Найдите “перенаправления” в документации вашего веб-хостинга, чтобы узнать, доступен ли какой-либо из этих инструментов.

404 Страницы

Когда браузер не может найти запрошенную веб-страницу, он выдает ошибку 404, указывающую на то, что файл не может быть найден. 404 страницы по умолчанию в браузере могут быть довольно простыми, поэтому вы можете захотеть создать пользовательскую страницу с более дружественным сообщением и, возможно, указателями на то, как пользователи могут найти то, что они ищут.

Большинство веб-платформ (например, Netlify, GitHub Pages и т.д.) Будут использовать файл с именем 404.html в корневом каталоге вашего веб-сайта в качестве пользовательской страницы с ошибкой, если вы ее предоставите. Вы можете включить пользовательскую страницу 404 на веб-сайт Quarto, создав файл markdown с именем 404.qmd в корневом каталоге вашего проекта. Например:

---
title: Page Not Found
---

The page you requested cannot be found (perhaps it was moved or renamed).

You may want to try searching to find the page's new location.

Обратите внимание, что вы можете использовать HTML наряду с markdown в вашем 404.qmd файле, чтобы получить именно тот внешний вид и компоновку, которые вы хотите.

Ваша страница 404 появится в Chrome вашего сайта (например, шрифты, css, макет, навигация и т.д.). Это сделано для того, чтобы пользователи не чувствовали, что они безвозвратно “ушли” с вашего сайта, когда получают сообщение об ошибке 404. Если вы не хотите такого поведения, то укажите 404.html вместо 404.qmd.

Вот несколько примеров того, как различные популярные веб-сайты обрабатывают пользовательские страницы 404: https://blog.fluidui.com/top-404-error-page-examples /.

website:
  title: "My Site"
  site-path: "/mysite/"

Обратите внимание, что если вы уже предоставляете site-url (который необходим для создания карт сайта и изображений предварительного просмотра социальных метаданных), то достаточно просто указать путь в site-url:

website:
  title: "My Site"
  site-url: "https://example.com/mysite/"

Пути к некорневым сайтам

Если ваш веб-сайт обслуживается из корневого каталога домена (например, https://example.com/), то для создания пользовательской страницы 404 достаточно просто предоставить 404.qmd файл, как описано выше.

Однако, если ваш веб-сайт не обслуживается из корневого каталога домена, вам необходимо выполнить одну дополнительную настройку, чтобы убедиться, что ресурсы (например, CSS вашего сайта) правильно разрешены на 404 страницах.

3. Создание блога

Обзор

Веб-сайты Quarto включают интегрированную поддержку ведения блогов. Блоги состоят из набора сообщений вместе с навигационной страницей, на которой они перечислены в обратном хронологическом порядке. Блоги могут включать пользовательскую страницу “О компании”, публиковать RSS-канал и использовать самые разнообразные темы.

Вы можете создавать веб-сайты, полностью состоящие из одного блога, веб-сайты с несколькими блогами, или вы можете добавить блог на веб-сайт, содержащий другой контент.

Краткое начало

Следуйте инструкциям Быстрого запуска выбранного вами инструмента, чтобы запустить простой блог. После ознакомления с основами читайте дальше, чтобы узнать о более продвинутых функциях блога.

Вот краткое описание ключевых файлов, созданных в рамках проекта starter blog:

Файл Описание
_quarto.yml Файл проекта Quarto.
index.qmd Домашняя страница блога.
about.qmd Страница о блоге.
posts/ Каталог, содержащий записи
posts/_metadata.yml Общие параметры для posts
styles.css Пользовательский CSS для веб-сайта

В следующих разделах мы подробнее рассмотрим различные компоненты проекта.

Домашняя страница

Домашняя страница - это страница со списком всех документов в posts каталоге:

Вот исходный код для домашней страницы:

---
title: "myblog"
listing:
  contents: posts
  sort: "date desc"
  type: default
  categories: true
---

Когда вы размещаете новую запись, страница со списком автоматически обновляется, добавляя самую последнюю запись в начало списка.

Не рекомендуется использовать динамические даты (например, today или last-modified) в своих публикациях в блоге. Это приведет к тому, что порядок вашего блога и ленты будет меняться каждый раз при визуализации или модификации документа.

Смотрите статью о страницах со списками, чтобы узнать больше о настройке списков, в том числе об использовании макета сетки, а не макета по умолчанию, показанного выше.

Категории

Страница со списком настроена так, чтобы включать категории, которые отображаются на правом поле страницы:

---
title: "myblog"
listing:
  # (additional metadata excluded for brevity)
  categories: true
---

Категории считываются с первой страницы документов, включенных в список.  Например, вот пример метаданных публикации, которые включают категории:

---
title: "Post With Code"
description: "Post description"
author: "Fizz McPhee"
date: "5/22/2021"
categories:
  - news
  - code
  - analysis
---

Каталог записей

Записи, составляющие содержимое блога, расположены в posts каталоге.

Добавьте новую запись в свой блог, создав в нем подкаталог posts и добавив index.qmd файл в этот каталог. Этот qmd файл является новой записью в блоге, и когда вы ее отобразите, домашняя страница блога автоматически обновится, чтобы включить самую новую запись в начало списка.

Черновики

Добавьте draft: true в параметры документа, если вы хотите, чтобы запись не была включена в список, карту сайта или поиск по сайту. Например:

---
title: "My Post"
description: "Post description"
author: "Fizz McPhee"
date: "5/22/2021"
draft: true
---

Чтобы опубликовать запись, когда она будет завершена, просто удалите draft: true из параметров документа, а затем отобразите ее.

Последнее обновление

Чтобы указать дату последнего изменения, но сохранить первоначальную дату публикации, вы можете добавить date-modified поле в параметры документа. Например:

---
title: "My Post"
description: "Post description"
author: "Fizz McPhee"
date: "5/22/2021"
date-modified: "5/23/2021"
---

Замораживание сообщений

Записи в блогах, содержащие исполняемый код, часто сталкиваются с проблемой, заключающейся в том, что записи, созданные в прошлом году, не могут быть отображены в этом году (например, из-за изменения пакетов, используемых в публикации). Аналогичная проблема также может возникнуть, когда в блоге участвуют несколько участников и не у всех есть подходящее программное обеспечение (или нужные версии) для отображения всех постов. Наконец, для отображения сообщений, содержащих вычисления, часто может потребоваться некоторое время, и вы не хотите, чтобы совокупное время, необходимое для отображения сайта, становилось слишком большим.

Решение этих проблем заключается в замораживании выходных данных вычислительных записей в блоге. При рендеринге публикации с помощью freeze: true сохраняются выходные данные markdown из базового движка (например, Jupyter или Knitr). Когда визуализируется весь сайт, эти вычисления не выполняются повторно, а скорее считываются из ранее замороженных результатов.

Статья с freeze: true отображается только тогда, когда вы явно повторно отображаете ее. Указав этот параметр для записей в блоге, вы можете гарантировать, что записи, отображаемые сейчас, всегда будут хорошо отображаться повторно на остальной части сайта, даже если программное обеспечение, необходимое для их первоначального отображения, недоступно.

В блог по умолчанию мы включаем файл (_metadata.yml), который устанавливает общие метаданные для всех документов в posts каталоге. В этом файле мы указываем, что мы хотим freeze: true установить по умолчанию для всех записей:

# options apply to all posts in this folder

# freeze computational output
freeze: true

Смотрите статью о freeze опции, чтобы узнать больше о замораживании результатов вычислений на веб-сайтах.

Блоги обычно включают RSS-канал, который позволяет легко распространять их контент среди читателей и на других веб-сайтах. Вы можете включить RSS для блога, выполнив следующие действия:

  1. В quarto.yml файле добавьте site-url и description к website ключу (без установки этих параметров в файле проекта Quarto не сможет сгенерировать ленту). Например:
website:
  title: "myblog"
  site-url: https://www.myblogexample.io
  description: "A great sample blog"
  1. На домашней странице вашего блога index.qmd добавьте feed: true опцию в список. Например:
---
title: "myblog"
listing:
  contents: posts
  sort: "date desc"
  type: default
  categories: true
  feed: true
---

Теперь при рендеринге вашего сайта также будет генерироваться RSS-канал.  Чтобы узнать больше, смотрите статью о RSS-каналах.

Включение RSS-ссылки на панель навигации

Вы можете добавить RSS-ссылку на панель навигации, включив следующее в _quarto.yml файл проекта. Например:

website:
  title: "myblog"
  site-url: https://www.myblogexample.io
  description: "A great sample blog"
  navbar:
    right:
      - icon: rss
        href: index.xml

Каналы категорий

Вы также можете создавать RSS-каналы для определенных категорий в своем блоге. Например, чтобы создать каналы для категорий news и posts в блоге, вы могли бы написать следующее:

---
title: "myblog"
listing:
  contents: posts
  sort: "date desc"
  type: default
  categories: true
  feed:
    categories: [news, posts]
---

Это создаст index.xml файл с RSS-каналом для листинга, а также index-news.xml и index-posts.xml файл с RSS-каналами для соответствующих категорий.

Обзор

Quarto включает поддержку полнотекстового поиска веб-сайтов и книг. По умолчанию Quarto автоматически проиндексирует содержимое вашего сайта и сделает его доступным для поиска с помощью локального индекса. Вы также можете настроить поиск по Quarto для использования размещенного индекса Algolia.

Внешний вид поиска

Поиск по умолчанию включен для веб-сайтов и книг. Если на сайте есть панель навигации, пользовательский интерфейс поиска будет отображаться на панели навигации, в противном случае он будет отображаться на боковой панели. Вы можете управлять местоположением поиска с помощью следующих опций:

Опция Описание
location navbar или sidebar (по умолчанию используется navbar, если таковой присутствует на странице).
type overlay или textbox (overlay предоставляет кнопку, которая открывает пользовательский интерфейс поиска, textbox выполняет встроенный поиск).

Например:

website:
  search: 
    location: navbar
    type: overlay

Обратите внимание, что приведенный выше пример отражает поведение по умолчанию, поэтому его не нужно указывать явно. Обратите также внимание, что поиск по веб-сайтам включен по умолчанию (вы можете отключить его с помощью search: false).

Использование Algolia

В дополнение к встроенной функции поиска, веб-сайты Quarto также могут быть настроены на использование внешнего поискового индекса Algolia. При рендеринге веб-сайта Quarto создаст файл JSON (search.json в выходном каталоге сайта), который можно использовать для обновления индекса Algolia. Подробнее о создании индексов с помощью Algolia см. в разделе Отправка и обновление ваших данных с помощью Algolia.

Базовая конфигурация

Для того, чтобы Quarto подключился к вашему индексу Algolia, вам необходимо предоставить основную информацию о подключении в вашем файле проекта Quarto. Вы можете найти эту информацию о подключении для вашего индекса Algolia на панели мониторинга в разделе “Ключи API”. Требуется следующая основная информация о подключении:

Опция Описание
index-name Название индекса, которое будет использоваться при выполнении поиска.
application-id Уникальный идентификатор, используемый Algolia для идентификации вашего приложения.
search-only-api-key API-ключ только для поиска, используемый для подключения к Algolia.

Важно

Обязательно используйте ключ API “Только для поиска”, который предоставляет доступ к вашему индексу только для чтения и безопасен для включения в файлы проекта. Никогда не используйте свой ключ API администратора в документе или проекте Quarto.

show-logo Отображает логотип ‘search by Algolia’ в нижнем колонтитуле результатов поиска.

Например:

website:
  search:
    algolia:
      index-name: <my-index-name>
      application-id: <my-application-id>
      search-only-api-key: <my-search-only-api-key>

Пользовательская схема индекса

Если вы просто используете search.json файл, созданный Quarto, в качестве индекса Algolia, приведенная выше информация о конфигурации - это все, что требуется для настройки поиска с помощью Algolia.

Однако, если вы создаете индекс каким-либо другим способом, вам может потребоваться предоставить дополнительную информацию, чтобы указать, какие поля Quarto следует использовать при поиске. Вы делаете это, добавляя index-fields ключ под algolia, который указывает названия определенных полей в вашем индексе.

Опция Описание
href

Поле, используемое для чтения URL-адреса этой записи индекса. Пользователь перейдет по этому URL-адресу, когда выберет соответствующий результат поиска. Обратите внимание, что Quarto группирует результаты по URL (не включая привязку при группировке).

Это поле обязательно для заполнения (либо как существующее поле в вашем индексе, либо с отображенным именем поля).
title

Поле, используемое для чтения заголовка индексной записи.

Это поле обязательно для заполнения (либо как существующее поле в вашем индексе, либо с отображенным именем поля).
text

Поле, используемое для чтения текста индексной записи.

Это поле обязательно для заполнения (либо как существующее поле в вашем индексе, либо с отображенным именем поля).
section

Поле, используемое для чтения раздела индексной записи. Quarto группирует результаты по URL и использует информацию о разделе (если таковая имеется) для отображения соответствующих подразделов одного и того же документа.

Это поле является необязательным.

Любое из вышеперечисленных действий может быть указано в вашем файле проекта Quarto. Например:

website:
  search:
    algolia:
      index-name: <my-index-name>
      application-id: <my-application-id>
      search-only-api-key: <my-search-only-api-key>
      index-fields:
        href: url
        section: sec
        text: body

Algolia Insights

По умолчанию Algolia предоставляет ряд аналитических данных, основанных на производительности вашего поиска в Algolia. Кроме того, может оказаться полезным более подробное отслеживание результатов, которые просматриваются и на которые нажимаются. Вы можете включить отслеживание кликов и конверсий с помощью Algolia, установив для analytics-events значение true:

website:
  search:
    algolia:
      index-name: <my-index-name>
      application-id: <my-application-id>
      search-only-api-key: <my-search-only-api-key>
      analytics-events: true

Вы можете подтвердить правильность отправки событий в Algolia с помощью отладчика событий. Обратите внимание, что клик и конверсии используем файлы cookie, чтобы поддерживать анонимный идентификатор пользователя—если печенье согласие включена, поиск по событиям, будет активна, только если печенье согласие не было дано.

Расширенная настройка

В дополнение к приведенной выше конфигурации вы также можете передавать специальные параметры Algolia при выполнении поиска. Например, вы можете захотеть ограничить результаты определенным аспектом или набором тегов. Чтобы указать параметры, добавьте params ключ в свой algolia yaml и укажите параметры. Для получения информации о доступных параметрах см. в разделе Параметры APIпоиска Algolia.

Например:

website:
  search:
    algolia:
      index-name: <my-index-name>
      application-id: <my-application-id>
      search-only-api-key: <my-search-only-api-key>
    index-fields:
      href: url
      section: sec
      text: body
    params:
      tagFilters: ['tag1','tag2']

Отключение поиска

Вы можете отключить поиск по отдельному документу, добавив search: false к документу метаданные. Например:

---
title: "My Document"
search: false
---

Если вы хотите отключить поддержку поиска для всего веб-сайта, вы можете сделать это, включив в свой _quarto.yml файл следующее:

website:
  search: false

5. Инструменты для веб-сайта

Верхние и нижние колонтитулы

Вы можете предоставить стандартные верхние и нижние колонтитулы для страниц вашего сайта. Они могут применяться к основному тексту документа или к боковой панели. Доступные опции включают:

Ценность Описание
body-header Уценка для вставки в начале текста каждой страницы (под заголовком и блоком автора).
body-footer Уценка для вставки под текстом каждой страницы.
margin-header Уценка для вставки содержимого над правым полем (т.е. оглавления).
margin-footer Уценка для вставки содержимого на правом поле.

Например (включены в _quarto.yml) :

body-header: | 
  This page brought to you by <https://example.com>
margin-header: |
  ![Logo image](/img/logo.png)

Обратите внимание, что ссылки на рисунки должны начинаться с /, чтобы работать на каждом уровне веб-сайта.

Социальные метаданные

Вы можете улучшить свой веб-сайт и публикуемый на нем контент, включив дополнительные типы метаданных, в том числе:

  • Значок

  • Карточки Twitter

  • Открыть график

Одна важная вещь, которую следует отметить при использовании инструментов для веб-сайтов, заключается в том, что, хотя эти инструменты добавляются на веб-сайты в website ключе, в книге вы должны включать те же опции в book ключе. Например, на веб-сайте вы должны включить значок и карточку twitter следующим образом:

website:
  favicon: logo.png
  twitter-card: true
  site-url: https://example.com

В книге вместо этого вы бы использовали book ключ:

book:
  favicon: logo.png
  twitter-card: true
  site-url: https://example.com

Читая документацию ниже, не забывайте заменять book на website, если вы являетесь автором книги.

Значок

Значок значка для вашего сайта предоставляет значок для вкладок браузера и других сайтов, которые ссылаются на ваш. Используйте favicon опцию, чтобы указать путь к изображению значка. Например:

website:
  favicon: logo.png

Карточки Twitter

Карточки Twitter обеспечивают улучшенный внешний вид, когда кто-то ссылается на ваш сайт в Twitter. Когда ссылка на ваш сайт включена в твит, Twitter автоматически сканирует ваш сайт и извлекает любые метаданные Twitter Card. Чтобы включить автоматическую генерацию метаданных Twitter Card для вашего сайта, вы можете добавить следующее в свой _quarto.yml файл конфигурации:

website:
  twitter-card: true

В этом случае Quarto автоматически сгенерирует заголовок, описание и изображение для предварительного просмотра содержимого. Дополнительные сведения о том, как Quarto находит изображения для предварительного просмотра, см. в разделе Предварительный просмотр изображений.

Вы также можете предоставить дополнительные метаданные, которые будут использоваться при создании карточки Twitter, в том числе:

Клавиша Описание
title Заголовок страницы. Quarto автоматически использует title метаданные из метаданных страницы. При желании вы можете переопределить это только для карточки Twitter, включив a title в twitter-card метаданные.
description Краткое описание содержимого. Quarto автоматически использует description метаданные из метаданных страницы. При желании вы можете переопределить это только для карточки Twitter, включив a description в twitter-card метаданные.
image

Путь к изображению предварительного просмотра для этого контента. По умолчанию Quarto будет использовать image значение из метаданных документа. Если вы предоставляете изображение, вы также можете при необходимости предоставить image-width и image-height для улучшения внешнего вида вашей карточки в Twitter.

Если image этот параметр не указан, Quarto автоматически попытается найти изображение для предварительного просмотра. Для получения дополнительной информации см. раздел Предварительный просмотр изображений.
card-style Либоsummary, либо summary_large_image. Если это не указано, лучший стиль будет выбран автоматически на основе других метаданных. Вы можете узнать больше о стилях открыток Twitter здесь.
creator @username создателя контента. Обратите внимание, что строки со специальными символами, такими как @, должны заключаться в кавычки в yaml.
site @username о веб-сайте. Обратите внимание, что строки со специальными символами, такими как @, должны заключаться в кавычки в yaml.

Вот более полный пример указания метаданных Twitter Card в quarto.yml файле:

website:
  twitter-card:
    creator: "@dragonstyle"
    site: "@rstudio"

Quarto автоматически объединит глобальные метаданные, найденные в website: twitter-card ключе, с любыми метаданными, предоставленными в самом документе в twitter-card ключе. Это полезно, когда вам нужно указать сочетание глобальных параметров (например, site) с параметрами для каждого документа, такими как title или image.

Открыть график

Open Graph protocol - это спецификация, которая обеспечивает более широкий обмен ссылками на статьи в Интернете. Это улучшит предварительный просмотр вашего контента, когда ссылка на него будет вставлена в такие приложения, как Slack, Discord, Facebook, Linkedin и другие. Чтобы включить автоматическую генерацию метаданных Open Graph для вашего контента, включите следующее в свой _quarto.yml файл конфигурации:

website:
  open-graph: true

В этом случае Quarto автоматически сгенерирует заголовок, описание и изображение для предварительного просмотра содержимого. Дополнительные сведения о том, как Quarto находит изображения для предварительного просмотра, см. в разделе Предварительный просмотр изображений.

Вы также можете предоставить дополнительные метаданные, которые будут использоваться при создании метаданных Open Graph, в том числе:

Клавиша Описание
title Заголовок страницы. Quarto автоматически использует title метаданные из метаданных страницы. При желании вы можете переопределить это только для метаданных Open Graph, включив a title в open-graph метаданные.
description Краткое описание содержимого. Quarto автоматически использует description метаданные из метаданных страницы. При желании вы можете переопределить это только для метаданных Open Graph, включив a description в open-graph метаданные.
image

Путь к изображению предварительного просмотра для этого контента. По умолчанию Quarto будет использовать image значение из site: метаданных. Если вы предоставляете изображение, вы также можете дополнительно предоставить image-width и image-height.

Если image этот параметр не указан, Quarto автоматически попытается найти изображение для предварительного просмотра. Для получения дополнительной информации см. раздел Предварительный просмотр изображений.
locale Язык, в котором помечены метаданные Open Graph.
site-name Имя, которое должно отображаться для всего сайта. Если это явно не указано в open-graph метаданных, Quarto будет использовать site:title значение.

Вот более полный пример указания метаданных Open Graph в quarto.yml файле:

website:
  open-graph:
    locale: es_ES
    site-name: Quarto

Quarto автоматически объединит глобальные метаданные, найденные в website: open-graph ключе, с любыми метаданными, предоставленными в самом документе в open-graph ключе. Это полезно, когда вам нужно указать сочетание глобальных параметров (например, site) с параметрами для каждого документа, такими как title или image.

Предварительный просмотр изображений

Вы можете указать изображение предварительного просмотра для своей статьи несколькими различными способами:

  1. Вы можете явно указать полный URL-адрес изображения для предварительного просмотра, используя image поле в соответствующих метаданных. Например:
title: "My Document"
twitter-card:
  image: "https://quarto.org/docs/websites/images/tools.png"
  1. Вы можете указать относительный путь документа к изображению (например, images/preview-code.png) или относительный путь проекта к изображению (например, /images/preview-code.png). Если вы указываете относительный путь, подобный этому, вы также должны указать site-url в метаданных вашего сайта. Например, в вашем _quarto.yml файле конфигурации:
website:
  site-url: "https://www.quarto.org"

и в вашем документе главное значение:

title: "My Document"
twitter-card:
  image: "/docs/websites/images/tools.png"
  1. Любое изображение, отображаемое на странице, также можно использовать в качестве предварительного просмотра, присвоив ему имя класса preview-image. Quarto выберет первое найденное изображение с этим классом. Например, следующее изображение будет использоваться в качестве предварительного просмотра при размещении на странице:
![](images/tools.png){.preview-image}

Если вы помечаете изображение этим классом, вы также должны указать site-url в метаданных вашего сайта.

  1. Если ни один из вышеперечисленных способов указания изображения предварительного просмотра не использовался, Quarto попытается найти изображение предварительного просмотра, выполнив поиск изображения, включенного в отрисованный документ, с одним из следующих имен: preview.png, feature.png, cover.png или thumbnail.png.

Google Analytics

Вы можете добавить Google Analytics на свой веб-сайт, добавив google-analytics ключ в свой _quarto.yml файл. В простейшей форме вы можете просто передать свой идентификатор отслеживания Google Analytics (например, UA-xxxxxxx) или идентификатор измерения тегов Google (например, G-xxxxxxx) следующим образом:

website:
  google-analytics: "UA-XXXXXXXX"

Кварто будет использовать сам ключ, чтобы определить, следует ли код Google аналитики (analytics.js) или тегов Google (gtag) по мере необходимости.

В дополнение к этой базовой конфигурации вы можете осуществлять более детальное управление аналитикой вашего сайта, используя следующие клавиши.

Клавиша Описание
tracking-id Идентификатор отслеживания Google или идентификатор измерения этого веб-сайта.
storage

файлы cookie - Используют файлы cookie для хранения уникальной идентификации пользователя и сеанса (по умолчанию).

нет - Не используйте файлы cookie для хранения уникальной идентификации пользователя и сеанса.

Подробнее о выборе вариантов хранения см. в разделе Хранилище.
anonymize-ip Анонимизируйте IP-адрес пользователя. Подробнее об этой функции см. в разделе Анонимизация IP-адресов (или маскирование IP-адресов) в Google Analytics.

Хранение

Google Analytics использует файлы cookie для распознавания уникальных пользователей и сеансов. Если вы решите использовать идентификационные файлы cookies для хранения этих данных пользователя, вы должны рассмотреть, действительно ли вам необходимо включить куки согласия для того, чтобы позволить зрителю управлять любым отслеживания, который можно включить.

Если вы выберете none для хранения, это приведет к следующим последствиям:

  • Для Гугл Аналитика В3 (analytics.js)
    нет отслеживания куки будут использоваться. Индивидуальный просмотров страницы будет правильно отслеживается, что позволяет вам увидеть, какие страницы просматриваются и как часто они рассматриваются. Отслеживание уникальных пользователей и сеансов не будет корректно сообщать данные, поскольку файлы cookie отслеживания, на которые они полагаются, не установлены.

  • Для тегов Google (gtag)
    Согласие пользователя на использование файлов cookie для отслеживания рекламы и аналитики будет сохранено. В этом режиме Google Analytics по-прежнему будет собирать пользовательские данные без идентификации пользователя, но в настоящее время эти данные не отображаются в отчетах Google Analytics.

Согласие на использование файлов cookie

Quarto включает в себя возможность запрашивать согласие на использование файлов cookie перед включением скриптов, которые устанавливают файлы cookie, используя согласие на использование файлов cookie.

Настройки файлов cookie пользователя автоматически контролируют Google Analytics (если они включены), а также могут использоваться для управления добавляемыми вами пользовательскими скриптами (см. Пользовательские скрипты и согласие на использование файлов cookie. Вы можете включить запрос согласия на использование файлов cookie по умолчанию, используя следующее:

website:   cookie-consent: true

Вы можете дополнительно настроить внешний вид и поведение согласия, используя следующее:

Клавиша Описание
type

Тип согласия, которое следует запросить, используя одно из этих двух значений:

подразумеваемый - (по умолчанию) Это уведомит пользователя о том, что сайт использует файлы cookie, и позволит им изменять настройки, но не заблокирует файлы cookie, если пользователь не изменит свои настройки.

express - Это блокирует файлы cookie до тех пор, пока пользователь явно не согласится разрешить их (или продолжит блокировать, если пользователь не согласен).
style

Стиль отображаемого баннера согласия:

простой - (по умолчанию) Простое диалоговое окно в правом нижнем углу веб-сайта.

заголовок - баннер во всю ширину в верхней части веб-сайта.

интерстициальный - полупрозрачный оверлей всего веб-сайта.

standalone - непрозрачное наложение на весь веб-сайт.
palette

Следует ли использовать темный или светлый внешний вид баннера согласия:

light - баннер светлого цвета.

темный - баннер темного цвета.
policy-url Ссылка на файлы cookie веб-сайта или политику конфиденциальности.
prefs-text Текст для отображения ссылки на настройки файлов cookie в нижнем колонтитуле веб-сайта.

Пользовательский пример может выглядеть скорее как:

website:
  cookie-consent:
    type: express
    style: headline
    palette: dark
  google-analytics:
    tracking-id: "G-XXXXXXX"
    anonymize-ip: true

Настройки файлов cookie

В дополнение к запросу согласия, когда новый пользователь посещает ваш веб-сайт, согласие на использование файлов cookie также добавит ссылку на настройки файлов cookie в нижний колонтитул веб-сайта. Вы можете управлять текстом этой ссылки с помощью prefs-text. Если вы предпочитаете разместить эту ссылку самостоятельно, просто добавьте ссылку с идентификатором #open_preferences_center на веб-сайт, и согласие на использование файлов cookie не добавит ссылку “Настройки” в нижний колонтитул. Например:

Пользовательские скрипты и согласие на использование файлов cookie

Согласие на использование файлов cookie предотвращает выполнение скриптов, если пользователь не выразил своего согласия. Для управления вашими пользовательскими скриптами используется согласие на использование файлов cookie:

  1. Вставьте теги скрипта как type='text/plain' (когда пользователь даст согласие, тип будет изменен на text/javascript и скрипт будет выполнен).

  1. Добавьте cookie-consent атрибут к своему тегу script, установив для него один из следующих 4 уровней:

    Уровень Описание
    strictly-necessary Строго говоря, скрипты загружаются автоматически и не могут быть отключены пользователем.
    functionality Скрипты, необходимые для базовой функциональности веб-сайта, например, запоминания языковых предпочтений пользователя.
    tracking Скрипты, которые используются для отслеживания пользователей, например, Google Analytics.
    targeting Скрипты, которые используются для таргетинга рекламы, например ремаркетинга Google AdSense.

Пример скрипта, который используется для отслеживания пользователей, будет выглядеть следующим образом:

<script type="text/plain" cookie-consent="tracking">

// My tracking JS code here

</script>

Ресурсы сайта

Помимо файлов ввода и конфигурации, ваш сайт, вероятно, также включает в себя различные ресурсы (например, изображения), которые вы захотите опубликовать вместе со своим сайтом. Quarto автоматически обнаружит все файлы, на которые вы ссылаетесь на вашем сайте, и скопирует их в выходной каталог (например, _site).

Если это автоматическое определение по какой-либо причине не выполняется, или если вы хотите опубликовать файл, на который нет явной ссылки на вашем сайте, вы можете добавить resources запись в свою конфигурацию. Например, здесь мы указываем, что хотим включить все электронные таблицы Excel в каталог проекта как часть веб-сайта:

project:
  type: website
  resources: 
    - "*.xlsx"

Обратите внимание, что *.xslx значение заключено в кавычки: это потому, что YAML требует, чтобы строки, начинающиеся не с буквенно-цифровых символов, были заключены в кавычки.

Вы также можете добавить resources значение метаданных к отдельным файлам. Например:

title: "My Page"
resources:
  - "sheet.xlsx"

Изображения являются наиболее часто используемым типом файлов ресурсов.  Если у вас есть глобальные изображения (например, логотип), на которые вы хотите ссылаться с различных страниц вашего сайта, вы можете использовать абсолютный путь сайта для ссылки на изображения, и он будет автоматически преобразован в относительный путь во время публикации.  Например:

![](/images/logo.png)

Веб-сайты Quarto могут поддерживать как светлый, так и темный режим. Например, вы можете использовать темы flatly и darkly (которые предназначены для использования в сочетании темного и светлого оформления) в качестве:

  light: flatly
  dark: darkly

Легкий Темный

При включении появится переключатель, который позволяет вашему читателю управлять внешним видом веб-сайта. Переключатель будет автоматически добавлен к навигации по веб-сайту следующим образом:

  1. Если была указана панель навигации, переключатель появится в правом верхнем углу панели навигации.

  2. Если навигационная панель отсутствует, но указана боковая панель, переключатель появится в том же месте, что и инструменты боковой панели (рядом с названием или логотипом на боковой панели).

  3. Если отсутствует панель навигации или боковая панель, переключатель появится в правом верхнем углу страницы.

Списки полезны для создания блогов, обеспечения навигации по большому количеству документов или в любом другом сценарии, когда вы хотите, чтобы содержимое страницы автоматически обновлялось по мере добавления, обновления и удаления документов.

Вы можете включить списки на странице, используя listing опцию во фронтальной части документа. Это проинструктирует Quarto генерировать дополнительный контент (‘списки’) при визуализации страницы. Например, следующий YAML в начале документа:
